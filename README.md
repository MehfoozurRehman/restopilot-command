# RestoPilot Command

A desktop point-of-sale and back-office workstation for restaurants, built with Electron and backed by a realtime Convex database.

## The problem

A restaurant counter needs order entry, table status, kitchen tickets, stock and purchasing in one place. Splitting those across separate tools makes it hard to see what is open, what is running low, and what the kitchen is working on. RestoPilot Command puts those jobs into one desktop app, with a route for each job and one shared data model behind it.

## What it does

- **Command dashboard** (`/command`). Shows revenue, open orders and the count of low-stock items at a glance.
- **Order entry and tables** (`/pos`, `/tables`). Builds an active order, adds products, changes item quantities and moves orders through statuses. Table layout is saved through `saveTable`.
- **Kitchen display** (`/kitchen`). A view for order tickets as they progress.
- **Menu, recipes and inventory** (`/menu`, `/inventory`). Materials carry stock levels and reorder thresholds, and recipes link products to the materials they use.
- **Purchasing** (`/purchase`). Records purchases from vendors against materials.
- **Guests, delivery and staff** (`/guests`, `/delivery`, `/people`). Covers customers, reservations, delivery orders, staff and shifts.
- **Finance and audit** (`/finance`, `/audit`). Expenses are recorded, and an audit log table is kept.

## How it's built

- **Desktop shell.** Electron 42 main process in `electron/main.ts`, with `contextIsolation` on and `nodeIntegration` off. A preload script in `electron/preload.ts` exposes the APIs the renderer needs.
- **Renderer.** React 19, TypeScript, Vite 8, React Router 7, Tailwind CSS v4 and Lucide icons. Client-side state uses Zustand (`src/store.ts`). The React Compiler is enabled through a Babel plugin.
- **Backend.** Convex, with an 18-table schema in `convex/schema.ts` covering products, recipes, orders, tables, staff, shifts, purchasing, reservations, deliveries and audit. Writes go through named Convex functions in `convex/restaurant.ts`, such as `createOrder`, `addProductToOrder`, `setOrderStatus` and `saveTable`.
- **Packaging.** `electron-builder` is configured with the app ID `com.restopilot.command`. The Windows target is an NSIS installer. Brand icons are generated by `scripts/generate-brand-assets.mjs`.

Two decisions shape the design:

1. **Business writes live in the backend.** The renderer calls named Convex mutations rather than writing records directly, so order and table rules sit in one place.
2. **Hardened renderer.** Context isolation is on and node integration is off, so the web UI cannot reach Node APIs directly.

## Running it locally

```bash
npm install
npx convex dev            # starts the Convex backend (needs a Convex project)
npm run electron:dev      # Vite plus the Electron app, with live reload
npm run dev               # web version only, at http://127.0.0.1:5173
```

Other scripts: `npm run build` (assets, type-check, Vite build and installer), `npm run build:web`, `npm run lint`, `npm run preview`.

## What I learned / what I'd do next

- There are no automated tests. The order functions in `convex/restaurant.ts` are the most valuable place to start.
- The README previously described offline tolerance and local caching. The only client store found is Zustand in memory, with no persistence or offline queue, so that description has been removed until it is built.
- `convex/restaurant.ts` exports a `seed` mutation. Review it, or gate it, before using the deployment for real trading.
- Vite starter assets remain in `src/assets/` (`react.svg`, `vite.svg`). Remove them if they are unused.
- The packaging config targets Windows only. macOS and Linux targets would need to be added if they are wanted.
